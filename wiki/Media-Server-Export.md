# Media Server Export

把下载的视频整理成 Jellyfin / Emby 可直接识别的目录：每个作品一个文件夹，里面有视频、封面和标准 NFO。

## 启用

1. 打开「设置 → 媒体服务器」，勾选「启用媒体库导出」；
2. 需要时修改「媒体库目录」（必须是绝对路径，且不能在下载目录或封面缓存内；留空使用默认位置 `<数据目录>/library`）；
3. 勾选「下载完成后自动导出」；
4. 点「导出全部已下载作品」处理已有的作品。单个作品也可以在作品卡片菜单里「导出到媒体库」。

![设置](images/settings.png)

5. 在 Jellyfin / Emby 里把这个目录添加为媒体库，类型选择「电影」或「家庭视频」。

## 导出的结构

```
library/
└── 作者名/
    ├── folder.jpg                      作者头像
    └── 标题 [作品ID]/
        ├── 标题 [作品ID].mp4           与下载文件是同一份（硬链接，跨磁盘时复制）
        ├── 标题 [作品ID].nfo           标准 <movie> NFO
        ├── poster.jpg                  封面
        └── .harbor.json                恢复清单（平台、作品 ID、作者、原始链接）
```

- 视频、封面、NFO 在同一个文件夹里；
- 封面来自本地缓存，没有缓存时依次尝试 yt-dlp 缩略图、重新拉取远程封面，最后从视频截取一帧；
- NFO 中的封面一律写相对文件名，不写会过期的远程地址；
- NFO 里 `lockdata` 为 `true`，防止服务器联网刮削覆盖本地信息；
- 图集作品（图片 + 音乐）也会导出为同样结构的文件夹，图片按顺序编号，背景音乐为 `.bgm.mp3`。

## 在 Docker 里让 Jellyfin / Emby 读到

把媒体库目录挂载出来，并让 Jellyfin / Emby 的容器挂载同一个路径：

```yaml
volumes:
  - ./data:/data
  - /你的媒体库路径:/data/library
```

## 文件名规则

- 非法字符 `\ / : * ? " < > |` 和控制字符替换为 `_`，避开 Windows 保留名；
- 标题取描述去掉话题标签后的第一行，最长 60 字，为空则用作品 ID；完整描述写入 `<plot>`，话题写入 `<tag>`；
- 作品 ID 始终在名字里，所以同标题不会冲突。

## 更新与冲突

- 重复导出是幂等的：硬链接已存在且大小一致则跳过，NFO 内容不变则不写；
- 在「编辑 NFO」里改过的内容**不会**被后续自动导出覆盖，只有单个作品手动导出时勾选覆盖才会重写；批量导出时也可勾选「同时覆盖我手动修改过的 NFO」；
- 勾选「删除下载任务时，同时删除对应的媒体库文件夹」后，删除任务会连带清理对应文件夹（只删清单里登记的文件）。

## 备份

网盘备份只需要同步媒体库目录：每个文件夹自带 `.harbor.json`，不依赖数据库就能知道它是哪个平台的哪个作品。设计细节见仓库 `docs/media-server-export.md`。
