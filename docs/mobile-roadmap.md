# 移动端功能计划：App 作为 Harbor 的远程控制台

目标变化：App 不只是“播放已下载的视频”，而是能替代网页端的大部分日常操作——**由 App 发起，服务端执行**。服务端已经有绝大多数接口（见下表），App 缺的主要是界面和少量增强接口。

> 优先级仍以网页端为主（见 `docs/mobile.md`）；本计划只在网页端稳定的接口上叠加 App 界面，不要求网页端先改。

## 一、服务端现有能力 → App 现状

| 能力 | 服务端接口 | App 现状 |
| --- | --- | --- |
| 立即同步（增量） | `POST /api/subscriptions/{id}/check`（只读新作品，遇到整页已知即停） | 无 |
| 全量同步历史 | `POST /api/subscriptions/{id}/sync` + `GET …/sync-progress` | 无 |
| 作品列表 / 状态统计 | `GET …/videos`（状态：已下载 / 下载中 / 未下载 / 失败 / 已取消 / 文件丢失）、`…/videos/stats` | 博主页只读显示“未下载”（0.7.0） |
| 单个下载 / 重新下载 | `POST …/videos/{vid}/download`（`redownload`） | 已有（博主页点未下载作品） |
| 批量下载 | `POST …/videos/download`，`video_ids` 为空 = 全部未完成；已下载自动跳过 | 无 |
| 清理丢失文件、删除记录 | `…/videos/orphan/cleanup`、`DELETE …/videos/{vid}` | 无 |
| 订阅增删改 | `POST/PATCH/DELETE /api/subscriptions`（间隔、自动下载、画质、NFO） | 无 |
| 任务队列 | `GET/POST /api/tasks`、取消 / 重试 / 删除、`/api/dashboard` | 无 |
| 链接解析与手动下载 | `POST /api/media/parse` + `POST /api/tasks` | 无 |
| 文件库 | `GET /api/files`、下载 / 打包 / 图集 / 字幕 / 元数据 | 只有流播放 |
| 导出到媒体库 | `POST /api/library/export`、`…/progress` | 无 |
| 直播 | `/api/live/subscriptions…`（检测、开始 / 停止录制、录制记录） | 无 |
| 代理与 Cookie | `/api/network…` | 无 |
| 日志、健康、设置 | `/api/logs`、`/api/system/health`、`/api/settings`（并发数） | 无 |
| 账号与 Token | 改密码、API Token 增删改、踢出其他会话 | 只有登录 / 退出 |

## 二、分阶段计划

### A. 订阅控制台（最先做，对应你举的例子）
- 新增底部 Tab“订阅”（或博主页里的操作栏）：订阅列表，显示昵称、平台、上次检查时间、已下载 / 未下载数、是否正在同步。
- 每个订阅一排操作：
  - **立即同步（增量）** → `check`，完成后显示“新增 N 个”。
  - **全量同步历史** → `sync`，用 `sync-progress` 轮询显示进度；同步中禁用其他操作（服务端会回 409）。
  - **全量下载（跳过已下载）** → `videos/download` 不传 `video_ids`。
  - **分批下载** → 选择“下一批 N 个”（20 / 50 / 100）或在作品网格里多选。服务端目前只有“全部”或“指定 id”：App 先用 `videos?status=not_downloaded` 取待下载列表，再按批提交 id；如果觉得慢，后续给接口加 `limit` 参数。
  - 重试失败的、清理文件丢失的记录。
- 订阅详情页：作品网格（带状态角标）、按状态筛选、多选下载 / 删除记录；下载中的作品显示进度（`task_progress`），完成后自动进入可播放的博主视频。
- 订阅设置：更新间隔、自动下载、画质、生成 NFO。
- 服务端需要补的：几乎没有；可选加 `limit`、以及同步结果里返回“新增列表”。

### B. 下载队列与手动下载
- “下载”页：任务列表（排队 / 下载中 / 完成 / 失败），进度与速度，取消 / 重试 / 删除。
- 粘贴分享文本或链接 → `media/parse` → 选画质 → 创建任务；也支持从系统“分享”菜单把链接发给 App（Android intent，需要新增原生配置）。
- 服务端需要补的：长任务的进度推送（目前靠轮询；可先用 3–5 秒轮询）。

### C. 文件库与图集
- 文件库列表（按作者 / 时间 / 类型），删除、重命名（服务端尚无，等网页端做）、导出到媒体库。
- 图集作品：feed 返回 `kind=gallery`，App 做轮播 + 背景音乐（原“图集”待办）。
- 服务端需要补的：`/api/feed` 增加图集类型。

### D. 直播
- 直播订阅列表、是否开播、开始 / 停止录制、录制记录与播放。
- 开播通知（见 F）。

### E. 系统与账号
- 服务状态（健康、磁盘、并发数）、代理与 Cookie 状态（Cookie 过期提示；扫码 / 内嵌浏览器登录无法在手机上做，只提示去网页端）。
- API Token 管理、改密码、退出其他设备；日志查看（排查下载失败）。

### F. 通知（可选）
- 下载完成 / 失败、订阅有新作品、开播提醒。需要服务端先有通知通道（现在“通知与机器人”未开始），App 侧用本地轮询通知或 FCM 之外的方案（国内机型 FCM 不可用，倾向轮询 + 前台服务）。

## 三、必须先处理的前提

1. **权限范围**：目前 API Token 持有即全权限。App 开始能删文件、改订阅、清 Cookie 之后，应该给 Token 加 scope（只读 / 下载 / 管理），并让 App 登录申请“管理”范围；高危操作（删除、清理、全量下载）在 App 里二次确认。
2. **长操作的状态**：全量同步和批量下载是长耗时任务，App 必须能“退出再进来”仍看到进度——一律以服务端状态为准（`sync-progress`、任务列表），App 只轮询展示。
3. **并发与限流**：批量下载会占满服务端并发（设置里的 `concurrency`），App 需要显示队列位置，避免用户反复点。
4. **导航**：底部导航会变成 首页 / 博主 / 订阅 / 下载 / 我的，较挤；建议把“系统与账号”收进“我的”，“文件库”放在“订阅”页内的入口。

## 四、建议的实施顺序

1. **A 订阅控制台**（立即同步 / 全量同步 / 全量下载 / 分批下载 / 作品状态）。
2. **B 下载队列**（任务列表 + 粘贴链接下载）。
3. **前提 1**（Token 权限范围）——在 C、E 之前完成。
4. **C 图集 + 文件库**、**E 系统与账号**。
5. **D 直播**、**F 通知**。

每一步一个 feat 分支、各自带后端测试（若有新接口）与 Flutter 测试。
