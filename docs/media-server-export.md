# Jellyfin / Emby 适配设计：媒体库导出

目标：每个作品在一个文件夹里，含**视频 + 封面 + NFO**，命名与结构让 Jellyfin / Emby 能直接识别；同一份文件夹也是后续接入网盘备份、灾难恢复的单位。不要求实际连接 Jellyfin/Emby 测试，只保证 NFO 是标准、可解析的 XML。

已确定：电影式 `<movie>` NFO；设置里开关"下载完成后自动导出"，另有"批量导出已有作品"和"单个作品手动导出"。

## 一、目录方案评估

现状：文件落在 `downloads/<任务UUID>/`，路径假设分布在资产登记、任务删除、订阅清理、NFO 定位等 6 处。

| 方案 | 优点 | 风险 |
| --- | --- | --- |
| A. 导出层：硬链接到独立的媒体库目录 | 下载、续播、删除、清理逻辑完全不动；同盘零额外空间；失败可重来 | 跨盘会退化为复制（占双倍空间）；两棵树都同步到网盘会重复上传，所以备份只指向媒体库目录 |
| B. 直接改下载目录结构 | 只有一份文件 | 要改 6 处路径假设并迁移已有数据；失败时容易丢文件 |

**结论：先做 A，并让媒体库目录自带"可恢复信息"，以后需要时再升级为 B（把媒体库目录升格为唯一正本）。** 灾难恢复要求每个作品文件夹自描述，所以每个文件夹里放一个 `.harbor.json`（见第四节），不依赖数据库就能知道它是哪个平台、哪个作品、哪个作者。网盘备份只同步媒体库目录；数据库另行备份。这样 A 和未来的 B 共用同一套文件夹格式，不会返工。

## 二、目录与命名

```
<媒体库根目录>/
  <作者>/
    folder.jpg                      作者头像（本地缓存的副本）
    <标题> [<作品ID>]/
      <标题> [<作品ID>].mp4         硬链接，失败回退复制
      <标题> [<作品ID>].nfo
      poster.jpg                    封面（见第三节）
      .harbor.json                  恢复清单
```

- 非法字符 `\ / : * ? " < > |`、控制字符替换为 `_`；去掉首尾空格和句点；避开 Windows 保留名（CON、NUL…）；整体按 UTF-8 字节截断（目录名 ≤ 120 字节），不拆断多字节字符。
- **标题**：抖音的描述常是"一段话 + 一串话题"。目录和 `<title>` 用描述去掉话题标签后的第一行，最长 60 字，空则用作品 ID；完整描述进 `<plot>`，话题进 `<tag>`。
- 作者目录重名（不同平台同昵称）时追加 `[<平台>-<用户ID>]`。作品 ID 始终在名字里，所以同标题不会冲突。
- 目录根必须是绝对路径、可写，且不能位于封面缓存或下载目录内部（防止互相扫描）。

## 三、封面（重点：缓存与时效）

问题：平台封面链接会过期，Jellyfin/Emby 的 NFO 如果写远程地址，过一阵就失效；封面缓存里只有部分作品，且格式可能是媒体服务器不认的 AVIF。

封面按顺序解析，取第一个可用的：

1. **本地封面缓存**（`var/covers`，已按作品页地址哈希，订阅同步和手动下载时就已落盘）→ 复制为 `poster.<ext>`。
2. **yt-dlp 已下载的缩略图**（YouTube 等，在任务目录里）。
3. **远程 `cover_url` 现拉一次**（还没过期时），写入缓存再用。
4. **用 ffmpeg 从视频抽一帧**（取总时长 10% 处，最多 3 秒后），保证永远有封面；清单里记 `cover_source: "frame"`，之后只要拿到真实封面，重新导出时会替换。

规则：
- NFO 里的 `<thumb aspect="poster">poster.jpg</thumb>` 一律写**相对文件名**，绝不写远程地址。
- 格式：JPEG / PNG / WebP 原样使用；AVIF、GIF、HEIC 用已有的 ffmpeg 转成 JPEG。
- 作者头像同样要缓存（它也会过期）：复用封面缓存，以头像地址为键。
- 封面缓存永不自动清理——它是封面的来源，也是批量重新导出的依据；导出后的 `poster.*` 是独立副本，网盘备份不依赖缓存目录。
- 批量导出结束会给出"封面缺失 N 个 / 用抽帧代替 M 个"的统计。

## 四、NFO 与恢复清单

NFO 是 Kodi 兼容格式的 `<movie>`（Jellyfin 与 Emby 都读）：UTF-8（无 BOM）、`<?xml version="1.0" encoding="utf-8" standalone="yes"?>`、所有文本经 XML 转义并剔除非法控制字符。

| 元素 | 来源 |
| --- | --- |
| `title` / `originaltitle` / `sorttitle` | 标题（见上） / 原始描述 / 标题 |
| `plot` | 完整描述 |
| `year` `premiered` `releasedate` | 发布时间 |
| `dateadded` | 下载完成时间 |
| `runtime` | 时长（分钟，向上取整）；另在 `fileinfo/streamdetails/video` 写宽高与 `durationinseconds` |
| `director` `credits` `studio` | 作者昵称 / 作者昵称 / 平台名 |
| `actor` | 作者：`name`、`role=创作者`、`thumb`（本地头像文件名） |
| `tag` `genre` | 话题标签 / 平台名 |
| `uniqueid type="<平台>" default="true"` | 作品 ID；`website` 写原作品页地址 |
| `thumb aspect="poster"` | `poster.jpg`（相对路径） |
| `lockdata` | `true`，防止服务器联网刮削覆盖本地信息 |

`.harbor.json`（恢复清单）：`schema`、`platform`、`work_id`、`source_url`、`author{id,nickname}`、`task_id`、`exported_at`、`files[{name,size}]`、`nfo_sha256`、`cover_source`。以后做"从媒体库目录重建数据库"只需扫描这个文件。

## 五、更新与冲突

- **幂等**：重复导出同一作品时，硬链接已存在且大小一致则跳过；NFO 内容不变则不写；写文件一律"临时文件 + 原子替换"。
- **用户手改保护**：清单里记录上次生成的 `nfo_sha256`；磁盘上的 NFO 与它不同，说明被手改过，自动导出不覆盖，只有"单个作品手动导出"勾选"覆盖"才重写。
- 现有"编辑 NFO"功能保存后，如果该作品已导出，自动把新内容同步到媒体库目录并更新清单哈希。
- 删除作品 / 订阅清理时，若设置了"同时删除媒体库文件夹"，一并清掉对应文件夹（仅限清单里登记的文件，不动用户自己放进去的文件）。
- 图集作品（图片 + 音乐）第一版**不导出**：Jellyfin 没有合适的"图集"类型，会放进"照片"库另议；批量导出统计里会列出"跳过 N 个图集"。

## 六、实现拆分

后端
- `backend/library_names.py`：命名清理、截断、话题提取（纯函数，重点测试）。
- `backend/library_nfo.py`：生成并校验 NFO（测试里用 `xml.etree` 解析回读，覆盖特殊字符、空字段、超长标题）。
- `backend/library_covers.py`：封面解析顺序、格式转换、ffmpeg 抽帧；复用 `covers.py` 的 `CoverCache`。
- `backend/library_export.py`：`Exporter`（单个、批量、进度），清单读写，冲突保护。
- 挂钩：`downloads.py` 任务完成处触发自动导出（设置开启时，失败只记事件，不影响下载结果）。
- 设置项：`library_enabled`、`library_root`、`library_auto`、`library_delete_with_work`；接口：`POST /api/library/export`（批量，后台执行）、`GET /api/library/export/progress`、`POST /api/subscriptions/{id}/videos/{vid}/export`。

前端
- 设置页新增"媒体服务器"分组：目录、开关、自动导出、批量导出按钮（沿用同步进度条样式）、覆盖统计。
- 作品卡片菜单与订阅"…"菜单加"导出到媒体库"。

测试
- 命名、NFO 解析回读、封面回退顺序（缓存 / 缩略图 / 抽帧）、硬链接与复制回退、幂等、手改保护、清单读写；不需要 Jellyfin/Emby。

## 七、已确认并实现
- 方案 A（导出层）；网盘备份只同步媒体库目录；图集不导出；媒体库根目录默认 `var/library`，设置里可改。
- 封面以哈希目录缓存（`var/covers`）为来源，导出后的 `poster.*` 是独立副本。
- 已知范围："删除时同时删除媒体库文件夹"目前只在删除下载任务时生效，订阅清理暂不联动；"编辑 NFO"已导出的作品编辑的是媒体库里的 NFO（媒体服务器读取的那份），未导出的仍编辑下载目录里已有的 NFO；手改过的 NFO 之后不会被自动导出覆盖。
